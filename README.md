# Ethical Hacking Learning System

A practical, evidence-driven 24-week learning system for a Windows-based Backend + AI Engineer. This repository is the working source of truth for the roadmap, notes, labs, engineering applications, progress and spaced revision.

## Start here
1. Read [the roadmap overview](roadmap/overview.md).
2. Follow the [24-week plan](roadmap/24-week-roadmap.md) in order.
3. Study one module at a time in [modules/](modules/).
4. Use the [learning workflow](guides/learning-workflow.md) for every submodule.
5. Record progress in [progress/submodule-tracker.md](progress/submodule-tracker.md), sessions in [progress/learning-log.md](progress/learning-log.md), and evidence in [progress/evidence-register.md](progress/evidence-register.md).
6. Schedule D+1, D+7, D+30 and D+90 reviews in [revision/revision-tracker.md](revision/revision-tracker.md).

## Completion rule
A topic is complete only when you can explain it independently, trace the relevant data/request flow, perform a safe repeatable exercise, test expected and negative cases, document evidence and pass delayed revision.

## Safety
Only assess systems you own or have explicit written authorization to test. Use isolated local labs and synthetic data. Never commit credentials, tokens, customer data, private keys, production exploit details or sensitive logs. Stop if testing risks availability, data exposure or scope violation.

## Repository map
- `source-material/`: provenance and reference notes for the original planning document.
- `roadmap/`: sequence, outcomes, cadence and learning rules.
- `modules/`: module-level concepts, practical tasks and exit criteria.
- `guides/`: repeatable study and lab workflow.
- `backend-ai-security/`: application of security to normal engineering work.
- `labs/`: safe lab setup and exercise records.
- `progress/`: status, study sessions and evidence.
- `revision/`: spaced repetition schedule and outcomes.
- `resources/`: trusted documentation and practice platforms.
- `capstone/`: final assessment deliverables and report templates.

The 24 weeks are a planning guide, not a deadline. Extend a module until its exit criteria are met.
